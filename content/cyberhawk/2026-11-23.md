This week's theme is package infrastructure trust: a compromised CA bundle shipped inside pip puts every Python developer at risk of a silent supply-chain MITM, while two critical npm packages — `simple-git` and `binary-parser` — ship injection flaws that can reach all the way to OS command execution. All three are in packages that indie devs pull directly, so check your lockfiles before the week is out.

## CVE-2026-133949 — pip bundles a certifi CA bundle containing compromised eMudhra certificates

**pip < 26.2.2 · PyPI · CVSS 9.3 · Published 2026-11-20**

**Are you exposed?** If you're running pip 26.2.1 or earlier (check with `pip --version`), your pip ships a certifi bundle that still trusts eMudhra intermediate CAs that were revoked after a key compromise. An attacker on the network path between you and PyPI — or a malicious mirror — could present a certificate issued under those intermediates to intercept or replace package downloads without triggering a TLS error. You're safe if you've already upgraded to pip 26.2.2+, or if your OS/Python runtime has revoked the eMudhra intermediates independently of pip.

**Fix** — `pip install --upgrade pip` to reach 26.2.2.

**If you can't patch** — pin package hashes in your `requirements.txt` (`pip download --require-hashes`) so a swapped package fails even if TLS is bypassed.

## CVE-2026-134815 — simple-git argument injection lets untrusted input reach OS command execution

**simple-git < 4.1.0 · npm · CVSS 9.2 · Published 2026-11-22**

**Are you exposed?** You're exposed if your app calls `listRemote(remote)` or `raw(args)` with any part of the input coming from an HTTP request, URL parameter, webhook payload, or other external source. An attacker can embed `--exec <command>` in the value; simple-git's `allowUnsafePack` guard does not cover these call paths, so git ends up executing the attacker's command in your Node.js process. If you only call simple-git with strings you hardcoded (e.g., `git.listRemote(['--heads', 'origin'])`), you're not affected.

**Fix** — `npm i simple-git@4.1.0`

**If you can't patch** — validate that no `listRemote()` or `raw()` argument starts with `--exec`, or strip `--` prefix args from any externally supplied input before passing it to simple-git.

## CVE-2026-134814 — binary-parser lets attacker-controlled schema options inject arbitrary JavaScript

**binary-parser < 2.3.1 · npm · CVSS 9.2 · Published 2026-11-22**

**Are you exposed?** You're exposed if you build a `Parser` using options (e.g., `length`, `key`, `tag`, `offset`, or `namely()`) whose values come from user input, a database row someone else can write, or an untrusted config file. These options are passed unvalidated to `Context.generateOption()` and compiled into executable JavaScript — classic code injection. If your parser schemas are entirely developer-authored constants with no external input shaping them, you're safe.

**Fix** — `npm i binary-parser@2.3.1`

**If you can't patch** — treat parser definitions as code, not data: validate that all string options are allowlisted values before passing them to `Parser`.
