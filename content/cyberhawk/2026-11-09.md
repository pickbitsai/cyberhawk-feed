This week is an npm-heavy one: two stored-XSS vulnerabilities in the SunEditor rich-text editor land alongside a critical sandbox escape in an expression-language library. Kubernetes operators running Kyverno 1.19.1 have a narrow but high-severity auth bypass to close, and anyone verifying SD-JWT presentations for authorization should check whether their logic handles missing claims safely. CISA KEV and NVD were unreachable from the digesting environment this run (network policy); sourcing is from the GitHub Advisory Database only.

## CVE-2026-124494 — SunEditor stored XSS via encoded `javascript:` href

**Headline:** SunEditor's link sanitizer passes encoded `javascript:` URIs — an attacker can store a link that runs JavaScript when a victim clicks it.

**Are you exposed?** You're exposed if your app renders SunEditor-produced HTML to other users — a CMS, a comment editor, a note-taking feature. The attack embeds something like `javascript&#58;alert(1)` in a link `href`; SunEditor's `_isSafeURL()` check sees the entity-escaped colon and passes it, but the browser decodes it before execution. If you run all stored SunEditor output through a strict server-side allowlist (DOMPurify, bleach with allowed tags) *after* saving it, you're likely protected regardless of SunEditor version.

**Fix:** Upgrade to `suneditor@3.4.0`.
```
npm i suneditor@3.4.0
```

**If you can't patch:** Before rendering stored content, strip any `href` values that — after HTML entity decoding — match `/^javascript:/i`.

## CVE-2026-124493 — SunEditor stored XSS via DocumentType header `innerHTML`

**Headline:** In SunEditor's document mode, heading text is written into `innerHTML` without escaping — stored entity-encoded HTML in an H1–H6 executes on editor load.

**Are you exposed?** You're exposed if you initialize SunEditor with `setOptions({ mode: 'document' })` and allow users to set heading content. The `DocumentType` constructor sets the heading's `innerHTML` from `textContent` directly, so a heading value of `&lt;img src=x onerror=fetch('/steal?c='+document.cookie)&gt;` becomes live markup the next time the editor loads the document. Standard paragraph mode (the default) is not affected by this specific code path.

**Fix:** Same fix — upgrade to `suneditor@3.4.0`.
```
npm i suneditor@3.4.0
```

**If you can't patch:** In any wrapper code you control, set heading content via `element.textContent =` rather than `element.innerHTML =`.

## CVE-2026-44267 — @enspirit/elo sandbox escape via `.constructor.constructor`

**Headline:** The `elo` expression evaluator has no denylist for `constructor` as a property name — any expression reaching user input can call `Function()` and execute arbitrary code in the Node.js process.

**Are you exposed?** You're exposed if you call `defaultFormats.elo.parse(userInput)` or run the `bin/elo` CLI against untrusted strings. The payload `({}).constructor.constructor('return process.env')()` works unmodified in affected versions (≤ 1.0.0). If you only pass your own server-side string literals to `elo.parse()` — never values derived from user input, URL parameters, or external data — you're safe.

**Fix:** Upgrade to `@enspirit/elo@1.0.1`.
```
npm i @enspirit/elo@1.0.1
```

**If you can't patch:** Reject any input containing the substring `constructor` before passing it to `elo.parse()`. It's a blunt filter but it blocks the known PoC.

## CVE-2026-124440 — Kyverno namespace isolation bypass via malformed `urlPath` percent-escapes

**Headline:** Kyverno 1.19.1 lets a namespace-scoped Policy's `apiCall` escape its namespace by appending malformed percent-encoded characters to `urlPath` — a tenant can read other namespaces' resources and create cluster-wide webhooks.

**Are you exposed?** You're exposed if you run Kyverno 1.19.1 on a multi-tenant Kubernetes cluster where untrusted namespace operators can create or update Policy objects with `apiCall` rules. The exploit lets them call the Kubernetes API as the admission-controller ServiceAccount, read resources outside their namespace, and create `MutatingWebhookConfiguration` objects — a path to cluster-admin. Single-tenant clusters, or clusters where only platform admins write Policies, are low-risk in practice.

**Fix:** Upgrade Kyverno to 1.19.2.
```
helm upgrade kyverno kyverno/kyverno --version 1.19.2
```

**If you can't patch:** Restrict `CREATE` and `UPDATE` RBAC permissions on `Policy` and `ClusterPolicy` objects to cluster-admin roles only until you can upgrade.

## CVE-2026-62374 — @sd-jwt/core silently drops tampered disclosures instead of rejecting the presentation

**Headline:** `@sd-jwt/core` and `@sd-jwt/decode` accept SD-JWT presentations with altered or malformed disclosures, returning a smaller claim set and a success result instead of an error.

**Are you exposed?** You're exposed if you verify SD-JWT presentations and make authorization decisions on the presence of a claim — for example, `if (claims.role === 'admin') { ... }`. An attacker who controls or intercepts a presentation token can corrupt a disclosure so that the `role` claim (or any other) disappears from the decoded result. If your authorization logic defaults to allow when a claim is absent, the check is bypassed. If you assert that required claims exist and throw or return 403 on their absence, the impact is reduced but you should still patch.

**Fix:** Upgrade `@sd-jwt/core` to `0.20.0`. Check project releases for a matching `@sd-jwt/decode` patch — it had no patched version listed at time of writing.
```
npm i @sd-jwt/core@0.20.0
```

**If you can't patch:** After `decodeSdJwt()` returns, explicitly verify that every claim your authorization logic depends on is present and non-null before trusting the payload.
