This week's theme: injection and authentication bypass. The lead story is unauthenticated remote code execution in Chainlit's MCP stdio transport — a public PoC is already circulating and no auth is required. Nodemailer patches an SMTP command injection that lets attackers silently add unauthorized email recipients. Rounding out the week, Rodauth ships a fix for a WebAuthn bypass that lets any logged-in user impersonate another account. All three have CVSS ≥ 9.3.

## CVE-2026-45018 — Chainlit MCP stdio: unauthenticated RCE with public PoC

Chainlit's `POST /mcp` endpoint accepts a user-controlled `fullCommand` string for stdio MCP transport. Validation only checks the executable name against an allowlist — not its arguments — so `npx -y -c 'id > /tmp/pwned'` bypasses the check entirely and runs arbitrary shell commands with Chainlit's process privileges. A two-step PoC (get a Socket.IO session, POST the payload) is already public. CVSS 9.8.

**Are you exposed?** If you run Chainlit with `features.mcp.enabled = true` on any server reachable from outside your network, you're exposed — the vulnerable code is in Chainlit's own server layer, not in your app. The flaw fires before any application-level auth check. If MCP is disabled or your Chainlit instance is locked to localhost/VPN only, you're safe.

**Fix:** `pip install "chainlit==2.12.0"`. The `fullCommand` parameter is removed entirely; stdio MCP servers are now declared in server config and selected by name at runtime.

**If you can't patch:** Set `features.mcp.enabled = false` in your Chainlit config immediately.

## CVE-2026-82854 — Nodemailer SMTP injection via `envelope.size`

Nodemailer before 8.0.4 concatenates `envelope.size` directly into raw SMTP command bytes without stripping CRLF characters. Injecting `\r\n` into that field lets an attacker append arbitrary SMTP commands — including extra `RCPT TO` lines that silently copy outbound email to attacker-controlled addresses. CVSS 9.3.

**Are you exposed?** You're exposed if you call `sendMail()` with a manually constructed envelope where `size` comes from user-supplied input:

```js
transporter.sendMail({ envelope: { from, to, size: req.body.size } })
```

If you let Nodemailer auto-construct the envelope (the common case — plain `{ from, to, subject, html }`) you're safe: Nodemailer does not include `size` in its default envelope.

**Fix:** `npm i nodemailer@8.0.4`

**If you can't patch:** Strip `\r` and `\n` from any user-supplied value before it reaches `envelope.size`.

## CVE-2026-82466 — Rodauth WebAuthn login authenticates as the wrong account

Rodauth before 2.46.0 has a logic error in the `webauthn_login` route: instead of binding the WebAuthn assertion to the account under authentication, the code falls back to the session's existing account identifier to complete the flow. A logged-in attacker can replay the WebAuthn challenge against a different user's ID and emerge with a session as that target account. CVSS 9.4.

**Are you exposed?** You're exposed if your Ruby app uses Rodauth with WebAuthn login enabled — `enable :webauthn_login` in your Rodauth configuration block. The attacker needs any valid session in your app, then targets another account's WebAuthn endpoint. Apps not using WebAuthn (password-only or OTP-only) are not affected.

**Fix:** Update `rodauth` to `>= 2.46.0` — `bundle update rodauth` in your app.

**If you can't patch:** Remove `webauthn_login` from your `enable` list, or require a full session logout before allowing WebAuthn authentication to begin.
