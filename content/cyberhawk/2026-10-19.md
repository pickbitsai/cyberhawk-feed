This week's five CVEs fall into two groups: default-insecure configurations that expose you silently (Airflow's SSH provider ships with host-key verification off; OpenNext's Cloudflare cache interception can be bypassed with encoded paths), and a cluster of AI/agent SDK issues that are landing as that ecosystem matures. If you're running Airflow pipelines or building with Claude Agent SDK, both need patches now.

## CVE-2026-94134 — Apache Airflow SSH/SFTP providers skip host-key verification by default

**Headline:** Every Airflow SSH and SFTP task is open to MITM credential theft unless you've explicitly hardened the connection.

**Are you exposed?** If you use `SFTPOperator`, `SSHOperator`, or any task with an SSH-type connection in Airflow, check your connection config. The default — no `host_key` set and no `no_host_key_check: False` override — silently disables verification. An attacker on the network path between your worker and the SSH server can impersonate the server and capture everything the task sends: credentials, private keys, file contents.

**Fix:** Upgrade `apache-airflow-providers-ssh` and `apache-airflow-providers-sftp` to 7.0.0. `pip install apache-airflow-providers-ssh==7.0.0 apache-airflow-providers-sftp==7.0.0`

**If you can't patch:** Set `host_key` to the server's public key fingerprint on every SSH/SFTP connection in the Airflow UI, or add `no_host_key_check: False` to each connection's extras.

## CVE-2026-100409 — @opennextjs/cloudflare middleware auth bypass via encoded paths

**Headline:** If you rely on Next.js middleware for auth on Cloudflare Workers, percent-encoded paths can skip it entirely.

**Are you exposed?** You're exposed if three conditions are true at once: (1) `enableCacheInterception: true` in your OpenNext config, (2) your middleware protects routes like `/admin/:path*`, and (3) a cached response exists for that route. A request to `/%61dmin` bypasses the middleware matcher but hits the `/admin` cache entry. If `enableCacheInterception` is not set (the default is off), you are not affected.

**Fix:** Upgrade `@opennextjs/cloudflare` to 1.20.2. `npm i @opennextjs/cloudflare@1.20.2`

**If you can't patch:** Remove `enableCacheInterception: true` from your config, or move auth checks inside route handlers rather than relying solely on middleware matchers.

## CVE-2026-96620 — Claude Agent SDK argument injection via `resume` option

**Headline:** Passing user-controlled input as a session ID to `sdk.resume()` lets an attacker run arbitrary commands at SDK startup.

**Are you exposed?** You're exposed if your code does something like `await sdk.resume(req.query.sessionId)` or `await sdk.resume(req.body.resumeToken)` — any pattern where a value from user input reaches the `resume` call. A value starting with a dash injects a CLI flag; specifically `--mcp-config` can define a stdio MCP server that executes arbitrary commands before your agent logic runs. If you generate session IDs server-side and never accept them from users, you are not affected.

**Fix:** Upgrade `claude-agent-sdk` to 0.2.121. `pip install claude-agent-sdk==0.2.121`

**If you can't patch:** Validate the session ID before passing it — reject any value that starts with a dash or contains characters outside alphanumerics and hyphens.

## CVE-2026-84994 — Qwik SSR server crash via crafted request body

**Headline:** One HTTP request crashes any Qwik SSR Node.js server running an unpatched version.

**Are you exposed?** If you run a Qwik app with server-side rendering on Node.js using `@builder.io/qwik` below 1.20.0 or `@qwik.dev/core` below 2.0.0-beta37, a single crafted request body causes an unhandled promise rejection that terminates the Node process. Edge runtimes (Cloudflare Workers, Deno) are not affected — this is a Node.js process-exit issue only. Any public-facing Qwik SSR server is vulnerable to trivial denial-of-service.

**Fix:** Bump to `@builder.io/qwik@1.20.0` or `@qwik.dev/core@2.0.0-beta37`. `npm i @builder.io/qwik@1.20.0`

**If you can't patch:** Put a reverse proxy in front that blocks requests with deeply nested or malformed body content, or use a process manager (PM2, systemd) to auto-restart on crash.

## CVE-2026-86063 — Claude Code plugin hash-pin can be bypassed via SHA-shaped branch names

**Headline:** Installing a Claude Code plugin and pinning it to a commit SHA doesn't guarantee you get that commit if the plugin repo allows SHA-named branches.

**Are you exposed?** You're exposed if you install plugins through Claude Code's marketplace (or any external plugin source) and the plugin's git host permits branch names that look like 40-character commit SHAs. The `git checkout <sha>` step resolves to a branch before a commit, so an attacker controlling the plugin repository can create a branch named after your pinned SHA and silently substitute their code. If you don't use plugins, you are not affected.

**Fix:** Update `@anthropic-ai/claude-code` to 2.1.179. Auto-update users already have this. `npm i -g @anthropic-ai/claude-code@2.1.179`

**If you can't patch:** Avoid installing plugins from repositories you don't control, or review installed plugin code manually after each update.
