AI/ML tooling dominated this week's critical advisories. A confirmed supply-chain attack targeting Python AI developers via semantic-router is the headline — if you have litellm 1.82.8 anywhere in your environment, your credentials have already been exfiltrated and rotation can't wait. Beyond that, a deepstream.io prototype pollution (CVSS 9.9) and a Fluentd RCE (CVSS 9.8) hit real-time and logging infrastructure, and a machine-learning fine-tuning UI shipped with auth controls that were CLI flags only — no backend enforcement at all.

## Supply-chain malware in litellm 1.82.8 exfiltrates cloud credentials on import

CVE-2026-42208

**Are you exposed?** Check `pip show litellm` right now. If the installed version is 1.82.8, the malware already ran — it ships a `litellm_init.pth` file that executes at Python startup before your code runs, collecting AWS IAM credentials, SSH keys, and all environment variables, then exfiltrating them AES-encrypted to `https://models.litellm.cloud/`. The trigger is installing it, not calling it. You're at risk if you installed semantic-router 0.1.8–0.1.14, since those versions had no upper bound on the litellm dependency and could resolve to the compromised wheel.

**Fix** — `pip install "semantic-router>=0.1.15" "litellm>=1.83.7,!=1.82.8"`. If litellm 1.82.8 was ever present on the machine, rotate every credential that was in environment variables or `~/.aws/` immediately — before you do anything else.

**If you can't patch** — There is no safe workaround for the compromised wheel. Uninstall it first (`pip uninstall litellm`), then rotate credentials.

## @deepstream/server prototype pollution allows privilege escalation (CVSS 9.9)

CVE-2026-49252

**Are you exposed?** You're exposed if you run `@deepstream/server` < 10.0.5 and any authenticated user can write records. A user with write access to a single record can send a record path containing `__proto__`, `constructor`, or `prototype` to pollute `Object.prototype` server-wide — enabling privilege escalation and potentially full server compromise. Read-only users or installations behind strict internal access controls are lower risk, but the CVSS is 9.9 because the attacker only needs a standard login.

**Fix** — `npm install @deepstream/server@10.0.5`

**If you can't patch** — Filter any incoming messages whose record paths contain `__proto__`, `constructor`, or `prototype` segments at the network or proxy layer before they reach deepstream's pipeline.

## Fluentd `${tag}` placeholder enables path traversal and RCE (CVSS 9.8)

CVE-2026-44024

**Are you exposed?** You're exposed if you use Fluentd ≤ 1.19.2 with `out_file` (or any file-writing output plugin) where the file path config includes `${tag}`, and your Fluentd instance receives log tags from sources you don't fully control — forwarded logs from external clients, Kubernetes pods with user-influenced labels, or logs shipped over the network. An attacker who controls a log tag value can inject `../../etc/cron.d/shell` to write arbitrary files, which Fluentd's advisory confirms escalates directly to RCE. If you feed Fluentd exclusively from internal services with fixed, hardcoded tag names, you're not exposed.

**Fix** — `gem install fluentd -v 1.19.3`, or pin `gem 'fluentd', '~> 1.19.3'` in your Gemfile.

**If you can't patch** — Remove `${tag}` from all file path patterns, or add an input filter that allowlists tag characters to alphanumeric and dots only.

## backpropagate `--auth` and `--share` flags are no-ops — UI has no backend auth (CVSS 9.3)

CVE-2026-48797

**Are you exposed?** You're exposed if you've run `backprop ui` (from the npm package `@mcptoolshop/backpropagate` or the pip package `backpropagate`) with `--auth user:pass` or `--share`, and that UI port is reachable from outside localhost — including via Cloudflare tunnels, ngrok, or a cloud VM's public IP. Both flags exist only at the CLI layer; no authentication middleware was wired into the Reflex backend in versions < 1.2.0. Anyone who reaches the port can trigger fine-tuning runs, read your uploaded training datasets, and push to HuggingFace using your stored HF token.

**Fix** — `pip install backpropagate==1.2.0` or `npm install -g @mcptoolshop/backpropagate@1.2.0`

**If you can't patch** — Don't expose the UI port outside localhost. Use SSH port-forwarding for remote access instead of `--share`.
