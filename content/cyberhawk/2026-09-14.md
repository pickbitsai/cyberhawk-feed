This week's digest is Python-heavy. A CVSS 10 RCE landed in Google's own Agent Development Kit, LiteLLM's AI gateway is on CISA's KEV list with confirmed in-the-wild exploitation, and Starlette (the core of FastAPI) joined the same KEV batch. Strapi picked up a stored XSS that lets Author-role users take over admin sessions, and a GitHub-reviewed prototype pollution hit a popular npm JSON:API library. If you're shipping AI-powered Python apps or running Strapi as your headless CMS, this week has at least two entries directly for you.

## CVE-2026-79696 — Google ADK for Python: unauthenticated RCE via test session replay

**CVSS 4.0: 10.0 (Critical)** — Published September 9, 2026

CVE-2026-79696

**Are you exposed?** You're exposed if you run the `adk web` command (ADK's built-in development/demo web server) in any environment where `pytest` is installed — including staging containers, Cloud Run, or GKE images that bundle dev dependencies alongside production code. An unauthenticated attacker can send a crafted test-session-replay request that bypasses an incomplete denylist in `config_agent_utils`, triggering pytest's import machinery to execute arbitrary code. If `adk web` is not running, or your deployment container has `pytest` cleanly absent, you're not exposed.

**Fix** — Upgrade to `google-adk>=2.7.0`:
```
pip install "google-adk>=2.7.0"
```

**If you can't patch** — Uninstall pytest from the container (`pip uninstall pytest`) and ensure it is excluded from your production image until you ship 2.7.0.

## CVE-2026-59822 — LiteLLM: authentication bypass on MCP Streamable HTTP endpoint

**CVSS 4.0: 8.8 (High)** — CISA KEV (confirmed active exploitation)

CVE-2026-59822

**Are you exposed?** You're exposed if you run LiteLLM as an AI gateway or proxy on any version below 1.84.0 and the MCP Streamable HTTP transport is reachable by an attacker (it is enabled by default in recent releases). Sending a fabricated `Authorization: Bearer <anything>` header triggers an OAuth2 passthrough fallback that replaces failed key validation with an empty `UserAPIKeyAuth()` object, giving full unauthenticated access to your MCP tooling. CISA confirmed attackers have deployed reverse shells and crypto miners via this path.

**Fix** — Upgrade to `litellm>=1.84.0`:
```
pip install "litellm>=1.84.0"
```

**If you can't patch** — Restrict the LiteLLM server to internal-only networking (VPN/private subnet/security group rule) so unauthenticated requests cannot reach it from the internet.

## CVE-2026-90561 — Strapi: stored XSS in content manager WYSIWYG preview

**CVSS: 8.7 (High)** — Published September 13, 2026

CVE-2026-90561

**Are you exposed?** You're exposed if you run Strapi 4.x through 4.26.2 or Strapi 5.x before 5.48.1, and your instance has users with the Author role (standard for multi-user content teams). An Author-level user can save a raw `<script>` tag inside a rich text field. When any Editor or Super Admin expands that entry's preview pane in the content manager, the script executes in their session — enough to steal the session token and take over the admin panel. A Strapi instance where only fully-trusted admins create content is not exposed in practice.

**Fix** — For v5, upgrade to `@strapi/strapi@5.48.1`:
```
npm i @strapi/strapi@5.48.1
```
For v4, check the [Strapi security advisories](https://github.com/strapi/strapi/security/advisories) for the patched 4.x release; the 4.26.2 branch is unpatched as of this writing.

**If you can't patch** — Remove the Author role from any untrusted user and restrict rich text creation to admins until you've upgraded.

## CVE-2026-48710 — Starlette: Host header injection enables route-level auth bypass

**CVSS: 6.5 (Medium)** — CISA KEV (confirmed active exploitation)

CVE-2026-48710

**Are you exposed?** You're exposed if you use Starlette below 1.0.1 — or FastAPI, which depends on it — and any of your middleware or route guards check `request.url.path` to enforce access control. Starlette before 1.0.1 builds `request.url` from the unvalidated HTTP `Host` header, so a malicious header can make `request.url.path` report a different path than what was actually routed, bypassing guards that rely on it. Guards that read from the raw ASGI `scope["path"]` instead are not affected.

**Fix** — Upgrade starlette directly, or upgrade FastAPI to a version that pins 1.0.1 or later:
```
pip install "starlette>=1.0.1"
```

**If you can't patch** — Rewrite auth middleware to read `scope["path"]` (the raw ASGI path, unaffected by the Host header) instead of `request.url.path`.

## CVE-2026-61534 — yayson: prototype pollution via JSON:API document `type` field

**Severity: Critical** — Published September 11, 2026 (GitHub-reviewed)

CVE-2026-61534

**Are you exposed?** You're exposed if you use `yayson` (npm, any 3.x or 4.x version through 4.2.0) to deserialize untrusted JSON:API payloads — for example, calling `Store.sync()` or `LegacyStore.sync()` with data from a third-party API response or user-controlled input. A document whose `type` field is `"__proto__"` writes onto `Object.prototype`, corrupting every object in the Node.js process. Minimum impact is a crash or logic corruption; if your application code has gadgets downstream of the polluted object (e.g. dynamic property access for routing or auth decisions), it can escalate to auth bypass or RCE.

**Fix** — Upgrade to `yayson@4.3.0`:
```
npm i yayson@4.3.0
```

**If you can't patch** — Validate that incoming documents' `type` field is not `__proto__`, `constructor`, or `prototype` before passing to `Store.sync()`, or launch Node with `--disable-proto=throw` to harden the prototype chain globally.
