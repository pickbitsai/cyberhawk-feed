A busy week across two major themes: AI tooling and foundational web infrastructure. Langflow — the open-source Python LLM app builder — disclosed ten critical CVEs in one batch, most still unpatched. WordPress issued an emergency auto-update to stop a pre-auth RCE chain (dubbed "wp2shell") being actively exploited in the wild. Rounding out the week: a path traversal bug in a widely-used npm archive library that can bite CI pipelines, a Node.js WebSocket parsing bug, and auth failures in two automation/agent platforms.

## CVE-2026-8481 · CVE-2026-8476 · CVE-2026-9198 · CVE-2026-9202 · CVE-2026-13446 (+ 5 more) — Langflow 1.0–1.10 has ten critical CVEs — RCE and unauthenticated access, most still unpatched

`langflow` (PyPI) versions 1.0.0 through 1.10.0 are affected by a cluster of ten critical CVEs. The most severe: two RCE vectors (CVE-2026-8481, CVE-2026-8476), unauthenticated chaining of `/api/v1` endpoints (CVE-2026-9198), unauthenticated unlimited user-account creation (CVE-2026-9202), and hard-coded credentials in the codebase (CVE-2026-13446). CVE-2026-8505 (webhook auth bypass — unauthenticated flow execution when `WEBHOOK_AUTH_ENABLE=False`, the default) is fixed in 1.10.1. The remaining nine CVEs have no patches as of 2026-07-20.

**Are you exposed?** You're exposed if you self-host any Langflow version from 1.0.0 to 1.10.0 and the HTTP port is reachable by untrusted clients. CVE-2026-9202 and CVE-2026-9198 require zero credentials — an attacker who can reach your Langflow port can create accounts and access API endpoints as any user. CVE-2026-8505 specifically: if you have any webhook-triggered flows, an unauthenticated caller who knows a flow's UUID can execute it and anything it runs, including Python code blocks.

**Fix:** Upgrade to `langflow==1.10.1` to close CVE-2026-8505. All other CVEs remain open — do not expose Langflow to the public internet regardless of version. Place it behind a VPN or authenticated reverse proxy, and set `LANGFLOW_AUTO_LOGIN=false` with explicit `LANGFLOW_SUPERUSER` / `LANGFLOW_SUPERUSER_PASSWORD` environment variables.

**If you can't patch:** Block all public inbound traffic to the Langflow HTTP port at the firewall or security-group level until remaining patches land.

## CVE-2026-60137 + CVE-2026-63030 — WordPress Core pre-authenticated RCE chain ("wp2shell") — emergency patch auto-pushed

A two-CVE chain in WordPress core yields unauthenticated remote code execution. CVE-2026-60137 is SQL injection in the `author__not_in` parameter of `WP_Query` (the class used by nearly every WordPress database call). CVE-2026-63030 is a REST API batch-route confusion bug in `WP_REST_Server::serve_batch_request_v1()` present since WordPress 5.6. Chained, they give pre-authenticated RCE. WordPress pushed an emergency auto-update and the chain is being actively exploited.

**Are you exposed?** You're exposed if your WordPress site is running 6.8.0–6.8.5, 6.9.0–6.9.4, or 7.0.0–7.0.1 and has not yet received the emergency auto-update. Any public WordPress installation is a viable target — no login required. Check your version at `/wp-admin/about.php` or via `wp core version` (WP-CLI). If your host disables auto-updates, you may still be on a vulnerable version.

**Fix:** WordPress auto-pushed 6.8.6, 6.9.5, and 7.0.2. Confirm you're on one of these. If not: `wp core update` (WP-CLI) or update via Dashboard → Updates. If you manage WordPress via a plugin like MainWP or Kinsta's admin panel, verify the emergency update propagated to all sites.

**If you can't patch:** Restrict access to `/wp-json/batch/v1` via your WAF or nginx config as a partial mitigation against the chain pivot, and block direct database query parameter injection at the WAF layer.

## CVE-2026-53486 — `decompress` (npm) path traversal — crafted archives can write files outside the target directory

`decompress` and its fork `@xhmikosr/decompress` fail to validate symlink/hardlink targets and use string-prefix matching for output path validation. A crafted archive can write files into any directory whose path prefix matches the output directory name (e.g., `/tmp/out-evil` bypasses a check intended to restrict to `/tmp/out`), and can create symlinks pointing outside the target before following them. In privileged environments (Docker build steps, CI install scripts, Node.js apps that extract user-uploaded archives), this can lead to arbitrary file overwrite or RCE. ~2.8M weekly npm downloads.

**Are you exposed?** You're exposed if your code calls `decompress(archiveBuffer, outputPath)` or `decompress(untrustedFile, dir)` where `archiveBuffer` or `untrustedFile` comes from user input, an external upload, or a fetched URL — and you're on `decompress@<10.2.1` or `decompress@>=11.0.0,<11.1.3`. Check with `npm ls decompress`. CI pipelines that extract user-supplied zip/tar files (e.g., plugin upload endpoints, build artifact handlers) are highest risk.

**Fix:** `npm i decompress@10.2.1` (or `@11.1.3` if on the v11 branch). If it's a transitive dep, add it as a direct dependency to force the version: `"decompress": "^10.2.1"`. For `@xhmikosr/decompress`, the fixed version is the same tag.

**If you can't patch:** Validate that all entries in an archive resolve to paths strictly inside the output directory before extracting, using `path.resolve()` and a prefix check on the resolved path.

## CVE-2026-54466 — `websocket-driver` (npm) before 0.7.5 — integer overflow corrupts server-side WebSocket message parsing

`websocket-driver` (npm) — the WebSocket protocol library used by Faye and `faye-websocket` — mishandles bytes with values `0x80` or above in frame length headers. A client can send a crafted sequence that overflows JavaScript's 64-bit float precision when parsing the length field, causing the server to misparse all subsequent message lengths and corrupt message routing in real-time applications.

**Are you exposed?** You're exposed if your Node.js app requires `websocket-driver` directly, or transitively through `faye`, `faye-websocket`, or any package that uses the Faye WebSocket implementation. Run `npm ls websocket-driver` — any version below 0.7.5 is affected. Apps using the `ws` package directly are not affected (separate implementation).

**Fix:** `npm i websocket-driver@0.7.5`. If it's a transitive dependency pinned at an older version, add `"websocket-driver": "^0.7.5"` as a direct dependency in `package.json` to force the resolution.

**If you can't patch:** Validate and reject WebSocket frames with non-standard byte values at your load balancer or proxy layer.

## CVE-2026-54052 — `n8n-mcp` 2.56.0 — cross-tenant workflow backup access leaks credential references

`n8n-mcp` (npm) version 2.56.0 and earlier, when run in multi-tenant HTTP mode (`ENABLE_MULTI_TENANT=true`), fails to isolate workflow version-history backups by tenant. Any authenticated user can read, list, and delete backup snapshots belonging to other tenants. Those snapshots contain full node definitions including credential references, API keys, and authorization headers embedded in workflow configurations.

**Are you exposed?** You're exposed if you run `n8n-mcp` with `ENABLE_MULTI_TENANT=true` in HTTP mode and have multiple distinct users or organizations sharing the same instance. Single-tenant deployments and stdio-mode deployments are not affected.

**Fix:** `npm i n8n-mcp@2.56.1`. After upgrading, rotate any credentials stored in n8n workflow nodes — assume other tenants on the same instance could have read them before the patch.

**If you can't patch:** Disable version-history backup features, or move to a single-tenant deployment until you can upgrade.

## CVE-2026-64622 — `network-ai` 5.12.2–5.13.3 — auth bypass exposes AI agent approval queues, no patch available

`network-ai` (npm), a tool for orchestrating AI agents with human-in-the-loop approval workflows, fails to enforce its configured auth secret on four GET routes: `/approvals/`, `/approvals/:id`, `/approvals/stats`, and `/approvals/sse`. A hardcoded `Access-Control-Allow-Origin: *` header further allows cross-origin reads from any browser tab. This is an incomplete fix of a prior bypass (GHSA-mxjx-28vx-xjjj) — the patch covered POST/mutation routes but left all GET routes open.

**Are you exposed?** You're exposed if you run `network-ai` versions 5.12.2 through 5.13.3 with an auth secret configured and the HTTP server reachable by untrusted clients. An unauthenticated attacker can read all pending approval requests including the shell commands, file paths, and justifications your agent queued for human review.

**Fix:** No patched version available as of 2026-07-20. Bind the `network-ai` HTTP server to `127.0.0.1` only — do not let it listen on `0.0.0.0` — and ensure no public network path reaches the approval routes.

**If you can't patch:** Firewall the `network-ai` port to trusted internal IPs only.
