AI tooling dominated this week's critical advisories. Langflow — the open-source Python LLM app builder used widely by indie AI developers — disclosed ten critical CVEs in a single batch, covering everything from unauthenticated account creation to remote code execution, with no patches available yet. Alongside that, a Node.js WebSocket parsing bug and auth failures in two popular agent/automation platforms round out a week where the theme is clear: AI infrastructure is moving faster than its security review.

## CVE-2026-8481 · CVE-2026-8476 · CVE-2026-9198 · CVE-2026-9202 · CVE-2026-13446 (+ 5 more) — Langflow 1.0–1.10 has ten critical vulnerabilities, no patches yet

`langflow` (PyPI) versions 1.0.0 through 1.10.0 (and 1.10.1 for CVE-2026-13446) are affected by a cluster of ten critical CVEs filed this week. The most severe: two separate RCE vectors (CVE-2026-8481, CVE-2026-8476), unauthenticated chaining of `/api/v1` endpoints to gain unauthorized access (CVE-2026-9198), unauthenticated unlimited user account creation (CVE-2026-9202), and hard-coded credentials in the codebase (CVE-2026-13446). Additional issues include arbitrary file write, privilege escalation, and webhook auth bypass.

**Are you exposed?** You're exposed if you self-host any Langflow version from 1.0.0 to 1.10.0. The unauthenticated account creation (CVE-2026-9202) and API chaining (CVE-2026-9198) issues require no credentials at all — an attacker who can reach your Langflow HTTP port owns the instance. If your Langflow server is publicly accessible, treat it as compromised until patched.

**Fix:** No patched version is available as of 2026-07-20. Do not expose Langflow to the public internet. If you must run it, place it behind a VPN or authenticated reverse proxy (nginx `auth_basic`, Cloudflare Access, etc.), and set `LANGFLOW_AUTO_LOGIN=false` with explicit `LANGFLOW_SUPERUSER` / `LANGFLOW_SUPERUSER_PASSWORD` env vars to block anonymous access paths.

**If you can't patch:** Block all public inbound traffic to the Langflow host — firewall or security group rule — until patches land.

## CVE-2026-54466 — websocket-driver before 0.7.5 — integer overflow corrupts server-side WebSocket message parsing

`websocket-driver` (npm), the WebSocket protocol library used by Faye and `faye-websocket`, mishandles bytes with values `0x80` or above in frame headers. A client can send a crafted sequence that overflows JavaScript's 64-bit float precision when parsing the length field, causing the server to misparse all subsequent message lengths. This corrupts message routing in real-time applications.

**Are you exposed?** You're exposed if your Node.js app directly requires `websocket-driver` or pulls it in via `faye`, `faye-websocket`, or any package that depends on the Faye WebSocket implementation. Check with `npm ls websocket-driver` — if you see any version below 0.7.5, you're affected. Apps using the `ws` package directly are not affected (different implementation).

**Fix:** `npm i websocket-driver@0.7.5`. If it's a transitive dependency showing up at an old version, add it as a direct dependency in `package.json` to force the upgrade: `"websocket-driver": "^0.7.5"`.

**If you can't patch:** Validate that WebSocket frames use standard ASCII byte ranges at the load-balancer or proxy layer.

## CVE-2026-64622 — network-ai 5.12.2–5.13.3 — auth bypass exposes AI agent approval queues, no patch available

`network-ai` (npm), a tool for orchestrating AI agents with human-in-the-loop approval workflows, fails to enforce its configured auth secret on four GET routes: `/approvals/`, `/approvals/:id`, `/approvals/stats`, and `/approvals/sse`. A hardcoded `Access-Control-Allow-Origin: *` header additionally allows cross-origin reads from any browser. This is an incomplete fix of a prior bypass (GHSA-mxjx-28vx-xjjj) — the patch protected POST/mutation routes but left GET routes open.

**Are you exposed?** You're exposed if you run `network-ai` versions 5.12.2 through 5.13.3 with an auth secret configured and the HTTP server reachable by untrusted clients. An unauthenticated attacker can read every pending approval request, including the shell commands, file paths, justifications, and risk-level annotations your agent was queuing for human review — without any credentials.

**Fix:** No patched version is available as of 2026-07-20. Bind the `network-ai` HTTP server to `127.0.0.1` only (do not expose it on `0.0.0.0`), and ensure no public network path reaches the approval routes.

**If you can't patch:** Add a firewall rule restricting the `network-ai` port to trusted internal IPs only.

## CVE-2026-54052 — n8n-mcp 2.56.0 — cross-tenant workflow backup access leaks credentials

`n8n-mcp` (npm) version 2.56.0 and earlier, when run in multi-tenant HTTP mode (`ENABLE_MULTI_TENANT=true`), fails to isolate workflow version-history backups by tenant. Any authenticated user on the platform can list, read, and delete backup snapshots belonging to other tenants. Those snapshots contain full node definitions, which include credential references, API keys, and authorization headers stored in the workflow.

**Are you exposed?** You're exposed if you run `n8n-mcp` with `ENABLE_MULTI_TENANT=true` in HTTP mode and have multiple distinct users/organizations on the same instance. Single-tenant deployments and stdio-mode deployments are not affected.

**Fix:** `npm i n8n-mcp@2.56.1`. After upgrading, rotate any credentials that were stored in n8n workflow nodes — assume other tenants on the same instance could have read them.

**If you can't patch:** Disable version-history backups in n8n-mcp config, or move to a single-tenant deployment until you can upgrade.
